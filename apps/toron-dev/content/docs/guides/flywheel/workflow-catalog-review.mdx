The built-in catalog currently contains **40 workflows**. This is not 40 independent ideas: it is a small set of lifecycle primitives, phase contracts, operational doors, and purpose-specific playbooks. The catalog keeps distinct behaviors separate where their evidence or supervision contract differs, while `workflow list --brief` gives agents a bounded selection surface.

## Selection rule

Use the smallest workflow that owns the contract you need:

1. **One phase or one operation:** choose a `phase-*` or operations workflow.
2. **A delivery path:** choose `goal` (bead-backed), `goal-direct` (explicitly no bead), `bug-fix`, `feature`, or `refactoring`.
3. **A comparison:** choose `prototype` for one model family, `arena` for model races, `debate` for a small adversarial synthesis, or `interrogate` for N-model review.
4. **A durable multi-step run:** choose a compose token: `wave-swarm`, `repair-until-verified`, or `beads-lifecycle`.
5. **Learning maintenance:** choose `ce-compound`, `ce-sweep`, or `reflect`.

Compound Engineering supplies the understand → plan → execute → review → verify → compound spine. pstack/poteto-mode supplies pickup, pause, babysit, shipping, and evaluation discipline. Neither justifies a second workflow engine or a prompt-only proof path.

## Operator overlays and freshness

`flywheel workflow seed` copies every compiled-in workflow, including the three
compose tokens, and every compiled-in stage into the user tier. It never
overwrites an existing user file, so an operator can edit a copy without
changing source. Resolution remains one path: built-ins &lt; user &lt; project.

`flywheel workflow drift` compares the user tier with the current built-ins and
labels each entry `missing`, `current`, `stale`, or `custom`. A stale copy is
still authoritative, by design, but it is visible rather than silently mistaken
for the new builtin.

## Failure policy

The R-E2 `error_kinds` declaration and its lint rule have been removed. The
field was never read by the engine, so retaining it made policy look
configurable while runtime behavior stayed centralized.

Retry and escalation now have one authority:
`FailureKind::is_retry_candidate()` retries `rate_limit` and `timeout`, while
`blocked`, `auth`, `cancelled`, and `unknown` escalate. Per-step retry overrides
require a real toron-workflow runtime contract and tests; they must not return as
YAML-only metadata.

## What was reduced

- **Discovery context:** `workflow list --brief` returns the GS-052 **hybrid** contract: **name / family / selection / run / topology / compose_token** (single live projection; topology kept for sticky-open). Bare `workflow list --json` adds full description, source, crew, inputs, steps/graph_nodes, and **decide_trigger**. `workflow show` emits name/source/description/run/compose_token/trigger/guard/crew/inputs/steps/graph/graph_nodes — **not** decide_trigger (or family/selection/topology).
- **Prompt authority:** stages carry reusable Compound/pstack contracts; workflow steps carry only local inputs, artifact paths, and control flow. A worker's `done` claim never replaces host verification.
- **Overlap:** similar workflows remain separate only when their supervision/evidence contract differs. The catalog now states those boundaries instead of asking an agent to infer them from long descriptions.
- **Long-running safety:** pickup, pause, babysit, autonomous work, and ship-beads remain operationally distinct; none creates a second loop or tracker.

Use:

```bash
flywheel workflow list --brief --json
flywheel workflow show <name>
flywheel workflow lint <name>
flywheel workflow seed --json
flywheel workflow drift --json
```

```text
$ flywheel workflow list --brief --json            # trimmed to the first entry
{
  "workflows": [
    {
      "compose_token": false,
      "family": "design-space",
      "name": "arena",
      "run": "workflow run arena --execute",
      "selection": "compare model arms; choose selection rule up front",
      "topology": "swarm"
    },
    …
  ]
}

$ flywheel workflow seed --json                    # trimmed
{
  "created_stages": [],
  "created_workflows": [],
  "kept_stages": ["baseline-measure", "bv-triage", "ce-brainstorm", …]
}

$ flywheel workflow lint wave-swarm ; echo $?      # clean lint is silent
0
$ flywheel workflow lint no-such-workflow-xyz ; echo $?
flywheel: unknown workflow "no-such-workflow-xyz" (flywheel workflow list)
1
```

`lint` printing nothing is the pass signal, so gate it on the exit code. `seed`
reporting empty `created_*` arrays with populated `kept_*` means the catalog was
already complete — the one state you want on a re-run.

If it fails: `unknown workflow` from `lint`/`show` means the name you have is
not in this host's catalog (stage names and workflow names come from the same
catalog, so check which you are holding). `drift --json` rows carry one of three
statuses per name — `current` (user tier matches the builtin byte for byte),
`missing` (no user copy; the builtin resolves), `stale` (a user copy shadows the
builtin and differs). `stale` is the one to stop on: a user copy always wins
resolution, so the guide you would follow from the builtin is not what runs.
