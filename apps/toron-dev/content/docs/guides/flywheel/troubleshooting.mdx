---
title: Flywheel troubleshooting
description: Named failures and their fixes. Door, spawn, loop, compose, and doorbell symptoms.
---

| Symptom | Meaning | Fix |
|---|---|---|
| Pane never leaves `unknown`, or a send reports `started:false` | The harness reports no OSC 7501 status, or the TUI is still booting | `hc read <t>` before resending (the text may have landed); an unreported pane is readable/typeable but not injectable, so its wakes are digest-bound |
| `unknown kind` at spawn | flywheel's catalog has no launch command for the kind | Add the kind to config `[kinds]`; hc itself has no agent-kind enum |
| Spawn exits 1, `swarm not ready` | `launch_pending` is normal | Wait; never add a second harness. Spawn fails closed after settle on any missing/empty/wrong-named pane |
| `flywheel status` shows `workspaces: []` right after spawn | Race between state write and status read | Trust the spawn verification; take names from the send error's `available:` list or `flywheel status / hc ls` |
| Send misses an idle agent | It did not miss: `prior_status: idle` means the brief landed | Only `landed: true` after `--wait`/`--confirm` counts as confirmed delivery |
| Beadless `--work` loop resolves `complete` instantly | Nothing to claim | Create lane beads first, or drop `--work` |
| Fresh loop parks after first poll | Stale loop invocation | `loop-mode doctor --fix`, relaunch |
| Held beads named `WaveGate` | Wave ordering, not a stuck owner | Close the lower wave; do not nudge |
| A pane waits for a ledger holder that does not exist; flips never land | The pane requested flips instead of checking the board | `toron reserve list`; no conformance holder means acquire it yourself (both glob levels), flip, commit, release. The ledger is a flip-scoped lease, never held between batches |
| Sibling beads in one crate are walled off | A blanket lease (`crate/**` or `crate/*`) | Release it and re-acquire exact files; never blanket a shared crate — siblings run in it |
| A pane reports "blocked on live peer" forever | Phantom block: no holder, or the holder is idle with nothing left to finish | Verify leases + fence + tree; when the block is phantom the captain orders the close and the pane commits and closes |
| Durable loop-mode panics or replay-storms | Poisoned invocation | `loop-mode doctor --fix`, then `loop-mode supervise <p> [--work]` (child `--once` passes, 3-strike stop) |
| A close refuses with "no legal PASS gate row" | The bead's legal gate differs (fence shape + band) | Read the refusal's "Legal gate names for this bead: X" and record THAT gate; `br close --dry-run` names it up front |
| Flood guard pause | More than 3 ready beads | One-poll pause, then dispatch resumes; not an error |
| `unknown compose token` / `unknown stage` | Installed binary predates the feature | Rebuild: `mbx +nightly-aarch64-apple-darwin install --path . --force`; verify from a non-repo cwd |
| `no flywheel swarm` | Wrong cwd or absolute path | Run `loop-mode run <slug> --work` from the parent workspace directory |
| Pane found but its name is `null` after a restart | Lost binding (the `toron_pin` label went with the old terminal) | `flywheel rebind` restores registered names; `recover` also respawns the dead |
| SIGKILL on the binary | Stale signature | `codesign --force --sign - ~/.cargo/bin/flywheel` |
| doorbell `answered by foreign owner, not child <pid>` | Port 18080/18980 conflict | Stop the foreign holder or relocate; arrival itself was unaffected |
| preflight `engine ... store unreachable` | Durable engine down | fix the store path and permissions, or run open-vehicle work and say so in the trail |
| Mail to `captain` fails | Alias cleared by parent death or never bound | `flywheel mail whois captain <p>` to check; `recover`/`adopt` rebinds; `toron contact captain --pin <pin>` sets it |
| `mode: standby` + `standby_with_known_workspaces` | Daemon adopted without hosts; zero wakes delivered | Arm it: `flywheel doorbell start <project>` for registry workspaces, or subscribe with `--project` and let auto-host fire within 60s |
| `doorbell start` adopts but hosts nothing | `--host` only rides a fresh serve spawn | `doorbell stop`, then start with `--host p/w`; or subscribe and wait one reconcile tick |
| Unit respawns hostless after `install` | launchd kept the stale loaded definition | `launchctl bootout gui/$(id -u)/com.doorbell.serve`, then `bootstrap` the plist; verify `hosted` in `/health` |
| Fresh binary SIGKILLed under launchd | Stale/missing ad-hoc signature | `codesign --force --sign - ~/.cargo/bin/doorbell ~/.cargo/bin/flywheel` |
| `doorbell`/`flywheel` behave like an older build | mise shims shadow `~/.cargo/bin` | Symlink shims at the fresh binaries, or remove the orphan shims |
| `mode: hosted`, nothing ever rings | The daemon cannot exec its CLIs. Under launchd `PATH` is `/usr/bin:/bin:/usr/sbin:/sbin`, so a bare `toron`/`hc` spawn fails as a child death: the watcher respawns on the retry gate and every inbox fetch audits `toron spawn/timeout failed` | Check `/health.binaries.resolved`; the daemon self-resolves `PATH` → `~/.cargo/bin` → `~/.local/bin` → beside its exe → mise shims (last). Pin with `DOORBELL_TORON_BIN`/`DOORBELL_HC_BIN`, reinstall, restart the unit |
| `/health.binaries.toron` points at a `mise/shims` path | A shim is a dispatcher: under launchd it dies with `mise ERROR No version is set for shim: toron` | Install the real binary (`~/.cargo/bin`) or set `DOORBELL_TORON_BIN` to it |
| `/health.degraded` shows `watch_restart_loop` | The watcher restarts far faster than its designed cadence (a quiet watcher idle-exits every ~109s) | Fix the CLI resolution above; confirm `ps ax | grep 'toron watch'` shows one live child per hosted workspace |
| `/health.degraded` shows `inbox_fetch_failing` | An `inbox_error` audit row in the last 120s: the sweep is failing | Read the `error` field in `doorbell/<ws>.audit.jsonl`; it names the cause |
| `/health.degraded` shows `inbox_store_skew` | The toron store is **ahead** of the binary the daemon shells (`/health.binaries.toron`): every inbox fetch refuses with `migration N is applied in <store> but this toron build resolves at most M`, so no wake can be fetched. The refusal carries a stable marker, `toron-error=store_skew`, which is what the daemon classifies on — grep the audit row for that token, not for the sentence around it. The row lands in `doorbell/<ws>.audit.jsonl` as `inbox_store_skew` (inbox arm) or `ack_sla_store_skew` (ack-SLA arm — the same shared store, refused at the same moment), and ONE workspace is proof — the store is shared. The probe matches the marker in any row, so either kind trips it | Reinstall toron from the source that wrote the store (`mbx +nightly-aarch64-apple-darwin install --path crates/toron-cli --force`), then restart the unit. Confirm with `toron --version` plus a direct call against the store: it must not name a ceiling (`toron ack-sla --project <p>` is the honest probe — it scans the durable root directly, so it fails where an inbox fetch routed through the daemon would not). Claiming the daemon is older is not enough here — the daemon may be current while the toron it shells is not. A skew also clears on its own once the last skew row is older than 120s, so re-read `/health` after a minute before calling it fixed |
| A pin has a cursor for every sibling but one, and `inbox_error` rows say `toron spawn/timeout failed` | Pre-fix behavior: `run_cli` piped the child's stdout/stderr and read them only **after** the child exited, and a pipe holds a finite buffer (65536 bytes on macOS). A cold `toron mail inbox --limit 50` page is 88925 bytes, so the child blocked in `write`, never exited, was killed at the 15s deadline and every byte was discarded — logged as a spawn/timeout failure for a fetch that had already succeeded. Self-reinforcing: the retry is equally cold | Fixed (2026-09-28): both pipes are drained on reader threads for the child's whole life. If you see this signature on a build older than that date, reinstall `doorbell` and restart the unit. Confirm the page is over the buffer with `toron mail inbox --as <pin> --project <p> --limit 50 --json \| wc -c` |
| Rows in `doorbell/<ws>.audit.jsonl` that do not parse as JSON | Two or more appenders wrote the same file, so their bytes interleave inside one line. Fixed 2026-09-28: a row is now serialized to a buffer and appended in ONE write, which is what `O_APPEND` makes atomic — the old writer streamed a `serde_json::Value` through `Display`, which emits the document fragment by fragment, and every fragment became its own append | Read `audit_torn_rows` in `/health`: `{workspace, torn, scanned, tear_after_age_s, newest_row_age_s}`, `null` when clean. `torn` counts only the last 256 KiB (the same bounded read every other probe uses), so a whole-file count is larger; the shell check is `python3 -c "import json,sys;print(sum(1 for l in open(sys.argv[1]) if l.strip() and not isinstance(json.loads(l),dict)))" doorbell/<ws>.audit.jsonl`. A tear is bounded from BELOW by the row in front of it, so `tear_after_age_s` is how old it is at least; `degraded: ["audit_rows_torn"]` means it is happening NOW |
| A subscribed identity never rings | A subscription buys the **sweep and an address, not a route**: it is now inbox-swept and `SelfIndex`-visible, but with no pane its wake is digest-bound, never a prompt | Read `doorbell digest <project> --identity <pin>`; to get a prompt, bind it to a spawned pin |
| `ack_sla_fired` audit row every 60s with the same `count` | Pre-fix behavior: the beat re-fired an unchanged backlog every scan | Fixed: the beat fires only on a **change** (new overdue ids, or `ack_sla_cleared`); a recurring row now means the backlog really is growing |
| A blocked agent keeps getting pinged (T0 → T1 → T2 → T3, then the loop halts) although it acked | Pre-fix behavior: the escalation climbed on elapsed time alone — the ack was never read, so an agent that answered looked identical to one that ignored the ping | Fixed: `notify_blocked` reads the agent's own `health-<name>` lane through `__ack-overdue --sla-secs 0` before each step; an ack resets the ladder. Still climbing? Run `flywheel __ack-overdue <project> <plane-name> --thread health-<name> --sla-secs 0` — `ok:false` means the read could not answer (no index, unregistered target, `[mail.toron] url` remote), and an unavailable read deliberately keeps the time ladder rather than silently stopping |
| Audit/journal unreadable — the ring's own evidence is buried | Usually one repeating producer, not many faults | Grep by `kind`: a pre-fix `inbox_error` storm, `registry_pin_stale` (each reaped pin, once), or a re-firing beat. Sweep fetches stop for registry pins whose pane the plane no longer has (`hc ls`) after a 120s grace |
| `mode: hosted`, `degraded: []`, yet no prompt ever lands | `hc ls` knows none of the registry pins' panes, so no wake can be injected — the ring's last hop is structurally impossible here | Read `/health.injection.prompt_hop` (`no_pane_in_plane`); start agents (`hc run --bg`) or fix the stale registry. Now also named as `no_injectable_panes` in `degraded` |
| `/health` accepts but never responds | Wedged runtime (seen: lock held across a reconcile loop) | `sample <pid>` for `lock_slow` parks; restart; the class is fixed, report a recurrence with the sample |
| `/health.wake.pipe.class` is `Deaf` (or `NeverStamped`) | Deaf: no event/hb frame inside `deaf_ceiling_ms` (default 60s) on the worst hosted workspace. NeverStamped: never observed a stamp (empty hosted / watch never wrote) — unknown ≠ deaf | Read `wake.workspace` (worst-of winner), `wake.last_event_ms` / `last_heartbeat_ms`, and `ps`/audit for that workspace's watch child; empty `wake.hosted` → re-arm with `--host`. Do not treat NeverStamped as Deaf |
| `/health.wake` Quiet but `watch.last_event_age_s` looks "alive", or Live when only heartbeats flow | Stamp-split lie: `.event` and `.hb` are separate (`watch-<ws>.event` / `.hb`); stuffing `max(event,hb)` into the event stamp collapses Quiet→Live | Trust `/health.wake`: `last_event_ms` is `.event` only, `last_heartbeat_ms` is `.hb` only; Quiet = hb live + no recent events |
| 20+ `spawn-*` subscriptions, `subscribers: 0` | Dead spawns never unsubscribed (pre-fix graveyard) | `flywheel doorbell unsubscribe <id>` each; `kill` now drops its own rows, daemon reaps week-silent ones |
| `flywheel mail …` fails: `migration N was previously applied but is missing in the resolved migrations` | The store was written by a newer embedded toron, or by the standalone `toron` on the same revision — this binary is behind. The message now names the store path and carries no destructive step | Reinstall at the current revision (`mbx +nightly-aarch64-apple-darwin install --path . --force`), or run the standalone `toron mail …` against the same project. The store is never dropped or rewritten |
| `briefing --commit` refuses: crew-confirm gate | Spawn-class topology without `--yes` (non-TTY) | Present the proposal to the operator, remix, rerun with `--yes` (or `--crew N`) |
| Every pane stops producing while `hc ls` still shows them alive | Wedged sessions: each turn failing silently (seen: provider 400 on replayed reasoning), zero CPU, no mail, no commits | Read one with `hc read <pane>`; respawn the swarm fresh (`flywheel spawn <p> --pi N --retire-orphans`), sweep the dead pins' holds (`toron reserve release --as <pin>`), reassign the open beads to the new pins |
| Loop passes fail preflight with `toron-error=store_skew` | The toron store is ahead of the binary — the standalone `toron` and flywheel's embedded copy both resolve an older migration | Rebuild from the source that wrote the store: `cargo install --path crates/toron-cli` and `mbx +nightly-<target> install --path . --force` in the flywheel repo; `captain watch --preflight` exits 4 naming the failing check and remedy |
| `flywheel recover <p>` refuses `invalid_agent_name` on a CamelCase pin | recover validated names as lowercase-only while the registry's pins are the mandated adjective+noun shape | The recover door accepts the pin shape; rebuild flywheel if the binary predates the fix |

## Escape costs

A raw `spawn --escape` forfeits SIGNOFF and artifacts. If you escape, you write the trail (timeline, beads) or it does not exist. Raw briefs drop the stage scaffold; the missing-close stalls observed in the fleet are the direct result, so `--raw` stays reserved for nudges and mail wakes.

## Where to look deeper

`flywheel timeline <p>` and `flywheel audit <p>` reconstruct events; `flywheel doorbell why --seq <n> --corr <id>` folds a tick from default; `flywheel artifacts <run_id>` lists typed records and `artifacts stitch` merges them. Fleet forensics references live in the flywheel skill's `references/forensics.md`.
