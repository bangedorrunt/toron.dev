toron is the signed transport and record layer: mail, identity, receipts, reservations, and the durable archive
underneath the other three planes. It is the clearest plane to start with, because a mailbox is something you can
watch work in ten minutes.

## Start on this site

<Card title="First signed handoff" href="/docs/guides/first-signed-handoff">
Install the daemon, register a pin, and exchange a sealed message with a receipt. Every step shows the output it
produces.
</Card>

<Card title="Survive a crash" href="/docs/guides/crash-recovery">
Kill the daemon mid-workflow and watch the run resume instead of restarting.
</Card>

## Every canonical guide

Every guide below is read here in full. The text is projected from `toron/docs/guides/` into this site and hashed on both sides, so the toron
repository stays the only place it is written and a copy edited here instead of there fails the build (ADR-0006).
Those guides are written as plain Markdown, and this site compiles MDX, so the projection escapes the two
characters that mean something else in MDX and quotes one frontmatter value. Commands, flags, and shown output are
untouched. The Canonical column names the file each page came from.

The reference grid for the 38-tool MCP surface is generated from `catalog/toron-mcp.json` on every build and pinned

checked the same way, and so is every projected page: a guide added in the toron repository without a
row here fails the build, and a projected page edited on this site instead of in the repository fails it too.
