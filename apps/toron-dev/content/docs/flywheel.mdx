flywheel turns a goal into crews, workflows, loops, and autonomous execution. It owns dispatch: who runs, what
they run, and what wakes them when they stop.

## Start on this site

## Every canonical guide

Every guide below is read here in full. The text is projected from `flywheel/docs/guides/` into this site and hashed on both sides, so the flywheel
repository stays the only place it is written and a copy edited here instead of there fails the build (ADR-0006).
Those guides are written as plain Markdown, and this site compiles MDX, so the projection escapes the two
characters that mean something else in MDX and quotes one frontmatter value. Commands, flags, and shown output are
untouched. The Canonical column names the file each page came from.

<Callout title="Where flywheel stops and beads starts">
flywheel decides what runs and proves a phase passed. It does not own the work item, the verification gate, or the
close record: those belong to beads, and a loop that cannot close its own work is the failure mode the
[beads section](/docs/beads) exists to explain.
</Callout>
