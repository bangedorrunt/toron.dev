toron is the signed transport and record layer underneath a larger autonomous agent workflow. It is one of four planes,
and it is the clearest one to start with because a mailbox is something you can see working in ten minutes.

## The rest of toron, in one command

```bash
toron daemon install
toron daemon start
toron doctor --check
```

```text title="You should see"
daemon installed · com.toron.serve
daemon started · 127.0.0.1:18080
doctor: 4/4 checks passed  (herdr ok · git ok · keys ok · store ok)
```

If it fails: `daemon install` refuses when an unmanaged process already holds the port. `toron daemon status`
distinguishes a managed instance from an unmanaged holder and names which one you have, which is the difference
between restarting and killing somebody else's daemon.

## Where the numbers come from

The tool pages under **Tools**, and the [reference grid](/docs/reference), are generated from `catalog/toron-mcp.json`
on every build. That catalog is the site's source of truth for tool names, schemas, resources, and CLI commands, which
is why a count on this site and a count in the product repository cannot quietly disagree.
