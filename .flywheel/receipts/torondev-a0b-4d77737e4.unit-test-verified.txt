The mechanism. The tile-to-page morph is React's own <ViewTransition>, not a hand-rolled
enhancer: the docs index tiles are next/link again, both sides of the pair are wrapped in
a named boundary in components/docs-content.tsx, and React assigns view-transition-name
and calls document.startViewTransition during the router's transition. The names React
writes were read out of the installed react-dom (getViewTransitionName returns a supplied
name verbatim), so the inline names are the four literals the stylesheet already pairs.

The island, and its bytes. components/morph-nav.tsx is deleted with it. Measured with the
same instrument as ADR-0009 on the same tree: the docs pages went 257.2 to 256.9 KB
gzipped, back under the number ADR-0009 recorded, because a client component in the docs
catch-all is registered per route. Gone with it: the pathname-watching settle signal, its
1500ms bail-out, and the whole class of bug that deadlocked the first build (a frame wait
inside a view-transition callback never returns).
