What was missing. `alternates` appeared nowhere under app/, so no page on the site named
itself. Two consequences, both real rather than theoretical: a Vercel preview deployment
serves the same pages from another hostname and neither host names the original, and the
docs publish a Markdown twin of every page at <path>.md (ADR-0005 D2), so a crawler
meeting both spellings had nothing to reconcile them with.

What shipped. `alternates: { canonical: "./" }` in the root layout, which is one line for
every route because Next resolves a relative canonical against the route being rendered,
and it keeps the origin where ADR-0005 D1 put it. The docs and blog generateMetadata name
themselves explicitly through absoluteUrl(page.url) and absoluteUrl(`/blog/${slug}`),
since those are the routes whose paths are computed rather than literal.

Read back out of the built HTML rather than the source:

  index.html        <link rel="canonical" href="https://toronmail.vercel.app">
  docs.html         <link rel="canonical" href="https://toronmail.vercel.app/docs">
  docs/toron.html   <link rel="canonical" href="https://toronmail.vercel.app/docs/toron">
  architecture.html <link rel="canonical" href="https://toronmail.vercel.app/architecture">
  blog/*.html       one per post, each naming its own slug

27 of the 28 built HTML files declare one. The 28th is .next/server/app/_global-error.html,
which is Next's own global error fallback rather than a route of ours, and it carries no
canonical in a stock app either.

The harness now asserts four of them (/, /docs, /docs/toron, /architecture), comparing
against the origin parsed out of lib/shared.ts rather than a copy of it, so a route that
loses its canonical fails a run. That check reads the built HTML, so it holds with no
server up.
